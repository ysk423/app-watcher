# 仕様書 — Google Play App Watcher

現状の実装に基づく機能仕様。内部設計は [design.md](./design.md) を参照。

最終更新: 2026-09-09（本番稼働中 / GitHub 自動デプロイ連携済み）

---

## 1. 概要

Google Play 上のアプリを毎日 1 回自動で追跡し、変化を記録して AI で分析する個人用ツール。

| | |
|---|---|
| 稼働環境 | Cloudflare Workers + D1（無料枠内） |
| URL | https://app-watcher.ysk-ino-123.workers.dev |
| 認証 | Basic 認証 |
| 監視上限 | 50 アプリ |
| 収集対象国 | 日本・米国の 2 か国 |
| AI | Google Gemini（既定: `gemini-3.5-flash-lite`） |
| ソース | GitHub `ysk423/app-watcher` |
| デプロイ | `main` への push で自動（Cloudflare Workers Builds） |
| 定期実行 | 10 分おきの Cron Trigger |

---

## 2. 認証

全ページが Basic 認証で保護される。

- 未認証のアクセスには `401` と `WWW-Authenticate: Basic realm="Secure Area"` を返す
- 認証情報は Cloudflare の Secret（`BASIC_AUTH_USER` / `BASIC_AUTH_PASS`）から読む
- **どちらかが未設定の場合、全ページが `500` を返して機能しない**（未設定のまま公開状態になることを防ぐ）

## 3. アプリの登録・管理

### 3.1 登録

| 項目 | 仕様 |
|---|---|
| 入力 | パッケージ名（例: `com.google.android.youtube`） |
| 形式検証 | 不正な形式は「パッケージ名の形式が正しくありません」で拒否 |
| 重複 | 既に登録済みなら「そのパッケージ名は既に登録されています」で拒否 |
| 上限 | 監視中が `MAX_APPS`（50）に達している場合は「監視中アプリが上限(50 件)に達しています」で拒否 |
| 即時取得 | 「登録後すぐに取得する」を選ぶと、その場で 1 回収集する |

即時取得は HTTP リクエスト内で完結する（1 アプリだけなので Cron を待たない）。

### 3.2 状態

アプリは以下の状態を持つ。

| 状態 | 意味 | 収集対象 | 上限にカウント |
|---|---|---|---|
| 監視中（`active`） | 通常の状態 | される | される |
| 停止中（`paused`） | 一時停止。履歴は保持 | されない | されない |
| 取得できません（`unavailable`） | Play から取得できない状態 | される（回復を検知するため） | される |

### 3.3 操作

| 操作 | 挙動 |
|---|---|
| 今すぐ取得 | その場で 1 回収集する |
| AI 分析を実行 | その場で AI 分析を 1 回実行する |
| 監視を停止 | `paused` にする。**履歴は保持される** |
| 監視を再開 | `active` に戻す |
| 永久削除 | 確認画面を経て、アプリ情報・スナップショット・レビュー・AI 分析・取得履歴を**すべて削除**する。元に戻せない |

### 3.4 取得できないアプリの扱い

Google Play から 404 が返る場合（アプリの公開停止・パッケージ名の誤りなど）:

- **自動削除はしない**
- 「取得できません」と表示し、過去のデータはすべて保持する
- スナップショット履歴には「取得失敗」として記録が残る
- 取得エラー履歴に日時と内容が残る
- 監視は継続されるため、アプリが復活すれば自動的に収集が再開される

## 4. データ収集

### 4.1 収集タイミング

Cron Trigger が 10 分おきに発火し、設定した開始時刻（既定 03:00 JST）を過ぎた最初の発火でその日のキューを作成する。以降の発火で 1 回あたり `collectBatchSize`（既定 2）件ずつ処理する。

- 1 アプリにつき 1 日 1 回
- 失敗した分はその日のうちに自動で再試行される（最大 3 回）
- 同じ日に何度収集しても、スナップショットは 1 日 1 行に上書きされる

### 4.2 収集対象の国

**日本と米国の両方**から収集する。1 アプリにつき 1 日 1 回、両国分をまとめて取得する。

Google Play は同じアプリでも国によって違う値を返すため、データは国ごとに分けて保存される。

| 項目 | 国による違い |
|---|---|
| **評価** | **国別集計**（YouTube 実測: 日本 3.24 / 米国 3.84） |
| レビュー | 国別（日本語レビューと英語レビューが別々に保存される） |
| レビュー件数 | 国別 |
| コンテンツレーティング | 国別（「12 歳以上」/「Teen」） |
| 価格・通貨 | 国別（JPY / USD） |
| カテゴリ・説明文・What's New | 言語別 |
| **評価件数・インストール数** | **全世界共通**（国間で比較しても意味がない） |

片方の国でだけ取得できない場合（その国で未配信など）でも、もう片方が取得できていれば収集は成功として扱う。両国とも取得できない場合のみ「取得できません」になる。

### 4.3 収集する項目

**アプリ詳細**

| 項目 | 備考 |
|---|---|
| アプリ名 / 開発者名 / 開発者 ID | |
| アイコン URL / ヘッダー画像 URL / スクリーンショット URL | 画像バイナリは保存しない |
| カテゴリ / 概要 / 説明文 | |
| 評価（スコア） | 例: 3.24 |
| 評価件数 / レビュー件数 | |
| インストール数 | 例: 10,000,000,000+ |
| バージョン | ※取得できない場合あり（4.5 参照） |
| Google Play 上の更新日 | |
| What's New（更新内容） | |
| 価格 / 通貨 / 無料かどうか | |
| アプリ内購入の有無と価格帯 | |
| コンテンツレーティング | |
| 広告の有無 | |
| 開発者メール / ウェブサイト / プライバシーポリシー | |
| Android 要件 | ※常に取得不可（4.5 参照） |

**レビュー**

1 回の収集につき新着順で最大 `REVIEWS_PER_FETCH`（既定 50）件。

| 項目 |
|---|
| レビュー ID / 投稿者名 / 評価（★） |
| 本文 / 高評価数 |
| 投稿時のアプリバージョン |
| 投稿日時 |
| 開発者からの返信と返信日 |

レビュー ID で重複を排除するため、同じレビューが二重に保存されることはない。

### 4.4 収集の失敗時

| ケース | 挙動 |
|---|---|
| 詳細取得が失敗 | その日は「取得失敗」として記録。既存データは削除しない |
| レビュー取得だけ失敗 | **収集は成功扱い**。詳細情報は保存される |
| 存在しないアプリ（404） | 再試行せず即座に打ち切る。「取得できません」と表示 |
| 収集中に再度収集が走った | 「すでに収集中のためスキップしました」を返す |

### 4.5 Google Play 側の制約

**Google Play は詳細ページからバージョンと Android 要件の公開を廃止している。**

| 項目 | 対応 |
|---|---|
| バージョン | 取得できない場合、**収集済みレビューの申告バージョンのうち最も新しいもの**を採用する。画面には「※Play 非公開のためレビュー申告値から推定」と表示 |
| Android 要件 | 代替手段が無いため常に空。画面には「Google Play 非公開」と表示 |

推定値は実際の最新バージョンより古い可能性がある（レビュー投稿者が古いバージョンを使っている場合）。出所は必ず画面に明示される。

## 5. AI 分析

### 5.1 3 つの機能

| 機能 | 実行タイミング | 内容 |
|---|---|---|
| 日次分析 | 収集完了後の Cron / 手動 | アプリ 1 件について「直近で何が起きたか」「レビュー傾向」「**国ごとの違い**」「注意すべき変化」 |
| 全体分析 | 収集完了後の Cron | 監視中アプリ横断で「全体のトレンド」「評価が伸びた / 落ちたアプリ」「**国による評価の違いが目立つアプリ**」「目立つ動き」 |
| Q&A | 手動 | 自由な質問に監視データを根拠に回答 |

### 5.2 Q&A の挙動

質問文に**アプリ名かパッケージ名が含まれる場合のみ**、そのアプリ（最大 2 件）のレビュー本文が AI に渡される。

- 「YouTube のレビューでよく指摘されている不満は？」→ レビュー本文に基づいて回答
- 「評価が最も低いアプリは？」→ 数値データのみで回答。レビュー内容には答えられない

これは AI に送るデータ量を抑えるための仕様である。レビューは日本・米国の両方が渡されるため、「日本と米国で不満に違いはあるか」といった比較にも答えられる。

### 5.3 AI が使えない場合

**いずれの場合もデータ収集は継続される。**

| 状況 | 表示 | 再試行 |
|---|---|---|
| API キー未設定 | 「GEMINI_API_KEY が設定されていません」 | 通常のリトライ（3 回） |
| 呼び出し上限に到達 | 「本日の Gemini 呼び出し上限(N 回)に達したため実行をスキップしました」 | **その日は自動再試行しない**。手動実行で再開 |
| レート制限（429） | 「Gemini API のレート制限に達しました」 | 同上 |
| モデル名が不正 | API のエラーメッセージをそのまま表示 | 通常のリトライ |

上限に達している場合、**API を呼び出さずに**スキップする（課金への移行を防ぐため）。

### 5.4 国別データの扱い

AI 分析は**両国のデータを 1 回の呼び出しにまとめて**行う。国ごとに分析を分けると Gemini の呼び出し回数が 2 倍になり、無料枠の上限に触れるためである。

分析結果には国ごとの違いを含めるよう指示している。

### 5.5 分析結果の保持

アプリごとに直近 30 件。それより古いものは日次メンテナンスで削除される。

## 7. データ保持

| データ | 保持期間 |
|---|---|
| スナップショット履歴 | **無期限**（削除しない。アプリ × 国 × 日で 1 行） |
| レビュー | 直近 90 日（国別に保存） |
| AI 分析結果 | アプリごと直近 30 件 |
| 実行履歴 | 直近 30 日 |
| キュー | 直近 30 日 |

削除は 1 日 1 回のメンテナンスで行われる（Cron に他にやることが無いときに実行）。

スナップショットは履歴そのものなので削除対象にしていない。100 アプリ × 365 日で約 40 MB と、D1 無料枠（**1 データベースあたり 500 MB**）に対しては小さい。

> **保持日数を伸ばすときの注意**: 無料枠は 1 データベースあたり 500 MB で、アカウント合計の 5 GB とは別の制限である。容量を圧迫するのはレビューで、100 アプリすべてが毎日 50 件の新規レビューを持つ最悪ケースでは 90 日で約 300 MB に達する。実行履歴は 365 日に伸ばしても 15 MB 程度で影響しない。ダッシュボードの「D1 ストレージ（概算）」で実使用量を確認できる。

## 8. バックアップ

D1 の Time Travel（ポイントインタイムリストア）を第一の手段とする。Worker からは実行できないためローカルから実行する。

```bash
wrangler d1 time-travel info app-watcher
wrangler d1 time-travel restore app-watcher --timestamp=<ISO8601>
wrangler d1 export app-watcher --remote --output=backup.sql
```

## 9. 更新とデプロイ

### 9.1 コードを変更したとき

`main` に push すると Cloudflare Workers Builds が自動でデプロイする。

```
git push  →  GitHub  →  Workers Builds  →  本番反映
```

ローカルから `npm run deploy` で直接デプロイすることもできるが、
GitHub のコードと本番が食い違うため、緊急時以外は push 経由にする。

### 9.2 設定を変更したいとき

変更したい項目によって手段が異なる。

| 変更したいもの | 手段 | 反映 |
|---|---|---|
| Gemini モデル・呼び出し上限・収集開始時刻・バッチ件数・保持日数 | **設定画面**から変更 | 即時 |
| 監視上限（`MAX_APPS`）・1 回のレビュー取得件数・ストレージ上限表示 | `wrangler.jsonc` の `vars` を編集して push | デプロイ後 |
| 認証情報・Gemini API キー | `wrangler secret put <名前>` | 即時（デプロイ不要） |

**設定画面での変更が最優先される。** `wrangler.jsonc` の値を変えても、
同じ項目が設定画面から保存されていると反映されない。その場合は設定画面側で変更するか、
D1 の `settings` テーブルから該当行を削除する。

> **シークレットは必ず `wrangler secret put` で登録すること。**
> Cloudflare ダッシュボードから「通常の環境変数（Text）」として追加すると、
> 次回のデプロイで `wrangler.jsonc` の `vars` に上書きされて消える。

### 9.3 スキーマを変更したとき

`migrations/` に新しい SQL を追加し、リモート DB へ適用する。

```bash
npm run migrate:remote
```

マイグレーションの適用は自動デプロイに含まれないため、手動で実行する必要がある。

**適用は push（＝自動デプロイ）より先に行う。** 順序を逆にすると、
新しいコードが存在しない列やテーブルを参照して本番が壊れる。

## 10. 制限事項

| 項目 | 内容 |
|---|---|
| バージョン | Google Play が非公開のため、多くのアプリでレビューからの推定値になる |
| Android 要件 | 取得手段が無く常に空 |
| 収集時間 | 50 アプリを既定設定で処理すると約 4 時間 10 分かかる（10 分 × 25 回） |
| バッチ件数 | 無料プランは Cron 1 回あたりの CPU 時間が 10 ms（実測 8.5〜11.6 ms）。「1 回の発火で収集する件数」を大きくすると上限に触れる可能性がある |
| Cron 本数 | 無料プランはアカウント全体で 5 個まで。本アプリは 1 個を使用 |
| Q&A のレビュー参照 | 質問文にアプリ名が含まれる場合のみ |
| Google Play の仕様変更 | HTML 構造が変われば収集が停止する。その場合は `src/collector/` の修正が必要 |
| 同時利用 | 個人用途を想定。複数ユーザーでの同時操作は考慮していない |

## 11. 動作確認済みの項目

ローカルおよび本番環境で、実データ・実 API による E2E 確認を実施済み。

| 対象 | 結果 |
|---|---|
| Basic 認証 | 未認証で 401、認証で 200 |
| アプリ登録＋即時取得 | YouTube・LINE で成功 |
| Google Play 実データ | 評価 / 評価件数 / インストール数 / カテゴリ / What's New / 更新日 |
| レビュー取得 | 50 件（★・投稿日・端末バージョン付き） |
| バージョン推定 | レビュー申告値からの補完と注記表示 |
| Cron 全遷移 | キュー投入 → 収集 → 分析キュー投入 → 分析 → メンテナンス |
| キューのリトライ | 3 回失敗で `failed`。後続タスクが停止しないこと |
| 取得不能アプリ | 自動削除されず「取得できません」表示 |
| 監視停止 / 再開 / 永久削除 | 関連データの連鎖削除を含む |
| 設定保存 | settings テーブルへの反映 |
| 登録上限 | `MAX_APPS=2` で登録拒否を確認 |
| Gemini 日次分析 / 全体分析 / Q&A | 実キーで成功 |
| 呼び出し上限到達時 | API を叩かず `skipped` として記録、収集は継続 |

**本番環境（Cloudflare）で確認したもの**

| 対象 | 結果 |
|---|---|
| Basic 認証 | 未認証で 401、認証で 200 |
| 認証情報の未設定時 | 全ページが 500 を返し、内容が露出しない |
| Google Play 実データ収集 | YouTube の登録＋即時取得に成功 |
| Gemini 日次分析 | 実キーで成功 |
| Cron Trigger | `Every 10 minutes` で登録済み |
| ストレージ表示 | `152 KB / 500 MB` と正しい上限で表示 |

**未確認**

- ブラウザでの見た目・ダークモード・レスポンシブ表示
- 「前回取得との差分」の実表示（2 日目のスナップショットが必要）
- `main` への push による自動デプロイ（Git 連携の設定は完了済み）
